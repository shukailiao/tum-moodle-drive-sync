# Security and privacy

- Never submit university passwords, cookies, session files, tokens, private course URLs or copyrighted materials in issues or PRs. Report vulnerabilities through GitHub private vulnerability reporting if enabled; otherwise contact the maintainer privately without including live credentials.
- Login is performed by you in a fresh browser window. This program does not read/fill password fields or bypass MFA, CAPTCHA or university controls. It does not reuse your normal browser profile.
- Only Moodle-origin cookies are saved, atomically, outside the checkout and output folder. No SSO identity-provider cookies or localStorage are persisted. Windows uses current-user DPAPI encryption. POSIX uses mode 0700 directories and 0600 files: these cookies are **not encrypted** there. Disk encryption is recommended. Malware running as your user can still use your session.
- Keep the default state path under your personal OS account. On Windows, its directory inherits your user-profile ACLs. A custom state path must have an ACL restricting access to you; DPAPI protects the session, but database/history/log metadata are not encrypted. Do not put state in shared/synchronized directories or copy it between users/machines.
- Requests verify HTTPS certificates, stay on the exact Moodle origin and do not forward cookies to other origins. Login alone uses the browser to follow legitimate SSO redirects. Scheduled sync never attempts automatic reauthentication.
- Only selected enrolled courses are processed. There is no public-course enumeration, enrolment or write API. Reading a Moodle page may still have Moodle's normal view/completion side effects.
- Requests are sequential (default one second between request starts), time out, and use bounded retries for transient request failures. Long Retry-After responses stop the operation. A failed stream is discarded and can be retried on the next run.
- Output paths are sanitized and checked for directory escapes. Existing files are never replaced or deleted by sync. Files are not extracted, opened, executed or published. Downloads are staged privately, then copied into exclusively created destination files; only this call's incomplete files are removed on handled failure. A forced process kill/power loss can leave a partial/orphan output file, which subsequent runs preserve and avoid overwriting. Google Drive may briefly observe a file during final copying; wait for both programs to finish.
- Output and state must be separate. Use a private, unshared Google Drive folder and respect course/university distribution rules. This program does not manage Google sharing permissions. `.gitignore` is a safeguard, not a data-loss-prevention system: output must stay outside Git checkouts, especially for unlisted file formats.
- `logout` deletes the local session file only; it does not revoke the Moodle session server-side or securely erase filesystem snapshots. Use Moodle's session management/logout to revoke access if necessary.
- Logs do not record request bodies, cookies, session keys or raw HTTP exception details. Logs/changelogs still contain course and file names; the SQLite database contains source URLs and local paths. Review and redact them before sharing.
